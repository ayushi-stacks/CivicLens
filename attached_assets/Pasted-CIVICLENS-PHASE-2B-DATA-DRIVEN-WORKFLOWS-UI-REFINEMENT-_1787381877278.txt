--------------------------------------------------
1. REPORT ISSUE
--------------------------------------------------

Use the existing Report screen.

Do NOT implement real CameraX, GPS or ML Kit yet.

Use the existing mock/demo detection values.

When "Confirm & Submit" is pressed:

- create an Issue in Room
- generate a unique issue ID
- save category
- save description
- save image URI
- save demo latitude/longitude
- save demo address
- save confidence
- set status to PENDING_VERIFICATION
- set verificationCount to 0
- set isSynced appropriately

Then:

- increment user's issuesReported
- award Civic Points
- create an Activity
- update StateFlow
- navigate through the existing flow

The new issue must become visible wherever appropriate without restarting the app.

--------------------------------------------------
2. DUPLICATE REPORT PROTECTION
--------------------------------------------------

Before creating an issue, perform a simple local duplicate check.

If an issue with the same category exists within approximately 50 meters, treat it as a possible duplicate.

Show a CivicLens-styled confirmation:

"Possible existing issue nearby"

Actions:

"View Existing Issue"

"Submit Anyway"

Do not create a completely new visual system for this.

Keep it consistent with the existing UI.

Do not implement image similarity yet.

--------------------------------------------------
3. ISSUE DETAILS
--------------------------------------------------

Make Issue Details fully Room-backed.

Load by issue ID.

Display existing fields:

- category
- description
- status
- location
- confidence
- verification count
- resolution confidence
- created date

Changes must automatically appear through StateFlow.

Do not manually reload the application.

--------------------------------------------------
4. VERIFICATION
--------------------------------------------------

Use the existing Verification screen.

When the user chooses:

"Yes, still there"
"No, it's resolved"
"Not Sure"

and submits:

- create Verification
- associate issue
- associate current user
- save result
- save comment
- save timestamp
- increment verificationCount
- recalculate confidence
- increment user's issuesVerified
- award Civic Points
- create Activity

Prevent duplicate verification by the same user for the same issue.

Update Issue Details automatically.

--------------------------------------------------
5. VERIFICATION CONFIDENCE
--------------------------------------------------

Use a simple deterministic calculation:

positive verifications / total valid verifications × 100

Handle zero safely.

Do not implement advanced statistical intelligence yet.

--------------------------------------------------
6. ISSUE STATUS
--------------------------------------------------

Use:

PENDING_VERIFICATION
VERIFIED
IN_PROGRESS
RESOLVED

Allow an issue to become VERIFIED when the local verification threshold is reached.

Do not implement municipal backend logic yet.

--------------------------------------------------
7. CIVIC POINTS
--------------------------------------------------

Centralize Civic Point calculations.

Do not scatter point values across Composables.

Use:

Accepted report: +50
Verification: +20
High-quality report bonus: +30
Resolution confirmation: +25

Make these values easy to modify later.

When points change:

- update User
- update Profile
- update Home
- create Activity

Points must never become negative.

--------------------------------------------------
8. ACTIVITY
--------------------------------------------------

Activity must be completely database-backed.

Create activities for:

- reports
- verifications
- resolution confirmations
- Civic Point rewards

Sort newest first.

Use the existing Activity UI.

Do not hardcode new activities in Composables.

9. HOME REACTIVITY

When a report is created:

- Issues Near You updates
- Civic Points updates
- Recent Activity updates

When a verification is submitted:

- verification-related counts update
- Civic Points update
- Recent Activity updates

No app restart.

No unnecessary manual refresh.
